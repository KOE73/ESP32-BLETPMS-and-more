/*
Samsung Galaxy SmartTag EI-T5300 — краткая шпаргалка BLE (для тестов)

1) Реклама (Advertising)
   • Service UUID: 0xFD5A (128-bit: 0000FD5A-0000-1000-8000-00805F9B34FB).
   • В service data присутствуют: версия протокола, Tag State (статусы: premature/offline/overmature/connected и т.п.),
     ageing counter, Privacy ID (rotating), уровень батареи, флаги (UWB/E2E), бит движения, регион, подпись.
   • Service-data можно парсить без спаривания — даёт состояние и батарею. 

2) GATT — основные сервисы/характеристики (неофициально)
   • Control / main service: использует FD5A-класс и/или кастомные UUID'ы вида DEE3xxxx-... (соответствующие характеристики):
     - DEE30004 — Battery (R).  
     - DEE30001 — Alarm / Ring (W/R/Ind/Notify) (включить/выключить сигнал).  
     - DEE30002 — Audio Volume (R/W/Notify).  
     - DEE30003 — Button / Button-config (events / config).  
     - DEE3000B — Firmware version (R).  
   • Есть отдельный сервис/характеристики для аутентификации/шифрования (пример UUID: eedd5e73-... и др.). 

3) Команды / форматы (практические)
   • Read Battery: читать DEE30004 → значения: 00 Very Low, 01 Low, 02 Medium, 03 Full.
   • Ring: write DEE30001 = 0x01 (on) / 0x00 (off).
   • Volume: DEE30002 — 0x01 low / 0x02 high (пример).
   • Button config: DEE30003 — биты для short/long press (пример: 0001 = enable short-press и т.п.).
   • Lost URL / OTA и др. — отдельные характеристики (hex-строка или зашифрованный blob). 

4) Криптография и ограничения
   • Большинство управляющих операций (ring, конфиг, OTA и т.п.) требует авторизации/шифрования — связь с SmartThings (или аналогом) использует защищённую сессию.
   • Privacy ID ротируется (~каждые ~15 минут по наблюдениям) и генерируется из ключей — усложняет постоянный трекинг. Без корректной аутентификации полнофункциональные write-команды не сработают. 

5) Быстрый чек-лист для автоматических тестов
   1. BLE-scan: найти рекламу с Service UUID 0xFD5A → распарсить service-data (получить Tag State, battery, Privacy ID). 
   2. GATT connect: перечислить сервисы и характеристики (ожидаемые DEE3xxxx и auth-service). 
   3. Try read Battery (DEE30004) — если возвращает значение, логировать. 
   4. Подписаться на нотификации Button (DEE30003) — эмулировать нажатие и смотреть нотиф. (может требовать auth). 
   5. Попытка write Ring (DEE30001) — ожидается отказ без сессии/аутентификации; для интеграционного теста используйте либо официальное SmartThings, либо патченый/референсный стек (uTag/пользовательские реализации). 

Источники и дополнительные разборы (неофициальные): community uTag/wiki (GATT таблицы и парсинг AD FD5A), реверс-исследования SmartTag / SmartThings Find (privacy ID, шифрование), аппаратные дампы и Wireshark-dissector — полезны для углублённых тестов. 
*/

/*
Samsung Galaxy SmartTag (EI-T5300) — BLE Advertising (Service Data 0xFD5A)
Пример разбора пакета, по данным community-reverse (uTag/wiki).

Advertising пакет обычно содержит:
 - Flags
 - Complete List of 16-bit Service UUIDs → 0xFD5A
 - Service Data (UUID: 0xFD5A) → именно там «всё самое интересное»

Пример сырых данных (hex):
  02 01 06 03 03 5A FD 17 16 5A FD 10 43 15 00 04 42 7F 9A 0E 62 20 07 10 01 30 01

Разбор поля Service Data (UUID 0xFD5A):

    bytes 0-1   → 5A FD              Service UUID (Bluetooth SIG Assigned, SmartTag)
    byte  2     → 10                 Protocol version / header marker
    byte  3     → 43                 Tag State (примерно: 01 Premature, 02 Offline, 03 Overmature, 04-06 Connected)
    byte  4     → 15                 Ageing counter (rotation / uptime ticks)
    byte  5     → 00                 Battery Level (00 Very Low, 01 Low, 02 Medium, 03 Full)
    byte  6     → 04                 Flags: bits (E2E on/off, UWB available, Lost mode, Motion detected и т.д.)
    bytes 7-8   → 42 7F              Region ID (или subtype/variant)
    bytes 9-11  → 9A 0E 62           Privacy ID (rotating, меняется каждые ~15 мин)
    bytes 12-15 → 20 07 10 01        Signature / checksum / reserved (используется для верификации)
    bytes 16-... может присутствовать (необязательные флаги, расширенные поля OTA/feature bits)

  "5AFD1043150004427F9A0E6220071001"
   5AFD            — Service UUID (FD5A)
     10            — Protocol version
       43          — Tag state (0x43 = connected/active)
          15       — Ageing counter
             00    — Battery level (Very Low)
               04  — Flags (UWB/E2E/Motion)
                 427F — Region
                     9A0E62 — Privacy ID
                            20071001 — Signature/reserved

BT Addr: динамический (в рекламе постоянно меняется вместе с Privacy ID)

Типичные поля в BLE Advertising:
  Flags → 0x06 (LE General Discoverable Mode, BR/EDR not supported)
  Complete List of 16-bit Service UUIDs → 0xFD5A
  Service Data (0x16) → [UUID FD5A + Payload выше]

Кратко по важным полям:
  • Tag State – отражает онлайн/офлайн режим.
  • Ageing Counter – увеличивается со временем (для защиты от replay).
  • Battery Level – 0-3.
  • Flags – набор битов (E2E = end-to-end crypto enabled, UWB = present, Motion = 1 если обнаружено движение).
  • Privacy ID – меняется каждые ~15 мин (в «Overmature» режиме раз в 24 ч).
  • Signature – часть схемы проверки/шифрования (AES / HMAC, закрытая часть протокола).

Используется для:
  • Обнаружения тегов в экосистеме SmartThings Find.
  • Оценки состояния (батарея, режим, движение) без спаривания.
  • Анализа BLE-пакетов в сканерах (nRF Connect, ESP32, BlueZ).

Источники (reverse-engineering, uTag/wiki, исследования SmartThings Find).
*/
