esp-idf библиотека или как организовать обмен событиями между частями программы

В ESP-IDF для организации обмена событиями между частями программы (между задачами или компонентами) используется встроенная библиотека esp_event, которая предоставляет мощный и гибкий механизм событийного цикла (event loop). Она идеально подходит для межзадачного взаимодействия в реальном времени на ESP32 и других микроконтроллерах Espressif. Давай разберём, как её использовать для передачи событий, и рассмотрим альтернативные способы, если она тебе не подойдёт.

Использование esp_event в ESP-IDF
esp_event позволяет компонентам программы отправлять события в общий цикл обработки, а другим компонентам подписываться на эти события через обработчики (handlers). Это особенно удобно для асинхронного взаимодействия между задачами FreeRTOS.

Основные шаги
Создание событийного цикла: Создаёшь цикл событий с помощью esp_event_loop_create() или используешь стандартный цикл (esp_event_loop_create_default()).
Определение событий: События идентифицируются двумя частями: базовый идентификатор (event_base) и ID события (event_id).
Регистрация обработчиков: Подписываешь функции-обработчики на конкретные события с помощью esp_event_handler_register().
Отправка событий: Отправляешь события в цикл с помощью esp_event_post() или esp_event_post_to().
Очистка: Удаляешь обработчики или цикл, если они больше не нужны (esp_event_handler_unregister(), esp_event_loop_delete()).
Пример обмена событиями
Вот пример, как организовать обмен событиями между задачами:

cpp
Перенос
Копировать
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "esp_event.h"
#include "esp_log.h"

static const char* TAG = "EVENT_EXAMPLE";

// Определяем базовый идентификатор события
ESP_EVENT_DEFINE_BASE(MY_EVENTS);

// Определяем ID событий
enum {
    MY_EVENT_BUTTON_PRESSED,
    MY_EVENT_DATA_READY
};

// Обработчик событий
void event_handler(void* arg, esp_event_base_t event_base, int32_t event_id, void* event_data) {
    if (event_base == MY_EVENTS) {
        switch (event_id) {
            case MY_EVENT_BUTTON_PRESSED:
                ESP_LOGI(TAG, "Button pressed!");
                break;
            case MY_EVENT_DATA_READY:
                ESP_LOGI(TAG, "Data ready: %s", (char*)event_data);
                break;
        }
    }
}

// Задача-отправитель
void sender_task(void* pvParameters) {
    esp_event_loop_handle_t* event_loop = (esp_event_loop_handle_t*)pvParameters;
    char* data = "Hello from sender!";
    while (1) {
        esp_event_post_to(*event_loop, MY_EVENTS, MY_EVENT_BUTTON_PRESSED, NULL, 0, portMAX_DELAY);
        vTaskDelay(2000 / portTICK_PERIOD_MS);
        esp_event_post_to(*event_loop, MY_EVENTS, MY_EVENT_DATA_READY, data, strlen(data) + 1, portMAX_DELAY);
        vTaskDelay(2000 / portTICK_PERIOD_MS);
    }
}

void app_main() {
    // Создаём событийный цикл
    esp_event_loop_handle_t event_loop;
    esp_event_loop_args_t loop_args = {
        .queue_size = 5,
        .task_name = "event_task",
        .task_priority = 5,
        .task_stack_size = 2048,
        .task_core_id = tskNO_AFFINITY
    };
    esp_event_loop_create(&loop_args, &event_loop);

    // Регистрируем обработчик
    esp_event_handler_register_with(event_loop, MY_EVENTS, ESP_EVENT_ANY_ID, event_handler, NULL);

    // Запускаем задачу-отправитель
    xTaskCreate(sender_task, "sender_task", 2048, &event_loop, 5, NULL);
}
Результат
Каждые 2 секунды задача отправляет событие MY_EVENT_BUTTON_PRESSED, затем MY_EVENT_DATA_READY с данными.
Обработчик реагирует и выводит сообщения в лог.
Преимущества esp_event
Асинхронность: События обрабатываются в отдельной задаче, не блокируя отправителя.
Гибкость: Поддерживает пользовательские события с произвольными данными.
Легковесность: Оптимизирована для ESP32, минимальный оверхед.
Модульность: Компоненты могут подписываться только на нужные события.
Альтернативы esp_event
Если esp_event тебе не подходит (например, слишком сложна или нужна ещё более простая реализация), вот другие способы организовать обмен событиями в ESP-IDF с FreeRTOS:

1. Очереди (Queues)
Используй xQueueSend() и xQueueReceive() для передачи данных между задачами.

cpp
Перенос
Копировать
QueueHandle_t event_queue;

void sender_task(void* pvParameters) {
    const char* message = "Event happened!";
    while (1) {
        xQueueSend(event_queue, &message, portMAX_DELAY);
        vTaskDelay(2000 / portTICK_PERIOD_MS);
    }
}

void receiver_task(void* pvParameters) {
    const char* received;
    while (1) {
        if (xQueueReceive(event_queue, &received, portMAX_DELAY) == pdTRUE) {
            ESP_LOGI("QUEUE", "Received: %s", received);
        }
    }
}

void app_main() {
    event_queue = xQueueCreate(10, sizeof(const char*));
    xTaskCreate(sender_task, "sender", 2048, NULL, 5, NULL);
    xTaskCreate(receiver_task, "receiver", 2048, NULL, 5, NULL);
}
Плюсы: Просто, надёжно.
Минусы: Один получатель на очередь, сложнее с несколькими подписчиками.
2. Уведомления (Task Notifications)
Используй xTaskNotifyGive() и ulTaskNotifyTake() для прямого уведомления задачи.

cpp
Перенос
Копировать
TaskHandle_t receiver_handle;

void sender_task(void* pvParameters) {
    while (1) {
        xTaskNotifyGive(receiver_handle);
        vTaskDelay(2000 / portTICK_PERIOD_MS);
    }
}

void receiver_task(void* pvParameters) {
    while (1) {
        if (ulTaskNotifyTake(pdTRUE, portMAX_DELAY)) {
            ESP_LOGI("NOTIFY", "Event received!");
        }
    }
}

void app_main() {
    xTaskCreate(receiver_task, "receiver", 2048, NULL, 5, &receiver_handle);
    xTaskCreate(sender_task, "sender", 2048, NULL, 5, NULL);
}
Плюсы: Очень лёгкий, без очередей.
Минусы: Только одна задача может ждать уведомления, данные передавать сложнее.
3. Группы событий (Event Groups)
Используй xEventGroupSetBits() и xEventGroupWaitBits() для передачи нескольких событий.

cpp
Перенос
Копировать
EventGroupHandle_t event_group;

void sender_task(void* pvParameters) {
    while (1) {
        xEventGroupSetBits(event_group, BIT0); // Событие 0
        vTaskDelay(2000 / portTICK_PERIOD_MS);
    }
}

void receiver_task(void* pvParameters) {
    while (1) {
        EventBits_t bits = xEventGroupWaitBits(event_group, BIT0, pdTRUE, pdFALSE, portMAX_DELAY);
        if (bits & BIT0) {
            ESP_LOGI("EVENT_GROUP", "Event 0 received!");
        }
    }
}

void app_main() {
    event_group = xEventGroupCreate();
    xTaskCreate(sender_task, "sender", 2048, NULL, 5, NULL);
    xTaskCreate(receiver_task, "receiver", 2048, NULL, 5, NULL);
}
Плюсы: Поддержка нескольких событий, несколько задач могут ждать.
Минусы: Ограничено битами (24 события), нет передачи данных.
Какой способ выбрать
Если нужно много подписчиков и данные: Используй esp_event — это стандартный и гибкий способ в IDF.
Если простое уведомление: Task Notifications — минимальный оверхед.
Если передача данных между двумя задачами: Queues — просто и эффективно.
Если несколько триггеров без данных: Event Groups — удобно для флагов.
Итог
В ESP-IDF встроенная библиотека esp_event — это твой лучший выбор для обмена событиями между частями программы, особенно если нужна масштабируемость и асинхронность. Если тебе нужно что-то проще, FreeRTOS даёт очереди, уведомления и группы событий. Попробуй пример с esp_event — он должен закрыть твои потребности. Хочешь конкретный пример под твою задачу?
